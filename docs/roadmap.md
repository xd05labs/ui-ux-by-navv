# Roadmap and completion boundaries

The original vision is preserved as an engineering roadmap. The v0.1 release includes a narrow end-to-end vertical slice through several later phases; that does not make the full later phases complete.

| Milestone | Intended scope | Current state |
| --- | --- | --- |
| v0.1 | Universal instructions and discovery | Implemented foundation |
| v0.2 | Schemas and industry blueprints | Initial schemas and 19 starter blueprints implemented |
| v0.3 | Themes and reusable components | Semantic token engine and workspace components implemented; full gallery pending |
| v0.4 | Frontend generators | Vanilla adapter implemented; framework adapters pending |
| v0.5 | Backend/API/database generators | WSGI/SQLite implemented; broader adapters and domain transactions pending |
| v0.6 | Visual/reference workflows | Interactive concept implemented; asset intelligence pending |
| v0.7 | Automated self-correction | Test evidence and failure workflow implemented; autonomous repair engine pending |
| v0.8 | Cross-LLM recovery | Portable entry files and checkpoint recovery implemented; host matrix verification pending |
| v0.9 | Plugins and deployment automation | Contracts and deployment files implemented; executable ecosystem and hosting automation pending |
| v1.0 | Validated public release | All applicable quality gates, benchmarks, docs and release review still required |

Next work should follow measured user needs: a second executable stack adapter, domain-specific transaction templates, a visual component gallery, stronger account lifecycle, comprehensive accessibility/performance evidence, explicit configuration migrations and provider evaluation runs. Keep each extension independently testable.
