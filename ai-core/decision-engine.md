# Decision engine

1. Preserve explicit user choices and existing project conventions unless a verified incompatibility requires discussion.
2. Prefer the simplest stack that meets real requirements. The local adapter fits private registers on one instance. Heavy concurrent writes, multi-region deployment or multiple replicas favor a reviewed PostgreSQL stack. SEO/server rendering favors an SSR adapter. These alternatives are agent-assisted in this release.
3. Recommend blueprint defaults for unanswered industry, layout, style and palette choices. Explain a recommendation briefly; label it a default until approved.
4. For a requested capability, consult `docs/capabilities.md`. Execute supported paths; provide an implementation plan for others. Generation must fail clearly rather than pretending an integration exists.
5. Prefer local assets and system fonts under privacy-first constraints. Do not call an LLM, upload a logo or fetch paid assets without authorization.
6. Assess changes to scope, models, auth and hosting against approved constraints. Re-plan affected decisions, preserve prior answers and record the reason.
