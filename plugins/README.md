# Plugin extension contract

Plugins are explicit, reviewed extensions, not modules automatically executed from a catalog. A proposed plugin supplies a manifest with id, version, capability requirements, configuration schema, input/output contract, compatible core version, security/privacy behavior and verification commands.

Use a new generator adapter for framework changes and integration adapters for payments, notifications, storage or analytics. Render into an in-memory map of relative paths; pass through path and collision checks before writing. Preserve existing features and migrations. Provide tests for both success and failure paths. Never let an uploaded manifest choose arbitrary imports, shell commands or file destinations.

There is no dynamic plugin runtime or marketplace in v0.1. Core changes require reviewed source edits and invalidate the approved source fingerprint.
